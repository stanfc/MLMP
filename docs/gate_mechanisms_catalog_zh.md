**更新：2026-06-22**

## 0. 先搞懂大背景：我們到底在解什麼問題？

### 0.1 任務：CTTA（Continual Test-Time Adaptation，持續測試時調適）
我們有一個已經訓練好的影像分割模型（NA-CLIP，做「開放詞彙語意分割」——把影像每個
像素分到一個類別，例如 road / sky / car）。問題是：**部署時遇到的影像跟訓練時不一樣**
（起霧、下雨、夜晚…），準確率會掉。

CTTA 的做法是：**在測試當下、沒有標準答案（label）的情況下，一邊預測一邊微調模型**，
希望它慢慢適應新環境。而且是「持續」的——影像一張一張不停進來（fog→night→rain→snow
一直循環 150 輪），模型**不能重置**，狀態一路累積。

**衡量指標 mIoU**：分割準確率，越高越好（0~100）。

### 0.2 核心矛盾（這整個研究的痛點）
- 會「進步」的方法（如 TENT、純 DeYO+MLMP）：剛開始 mIoU 上升，但**跑久了會崩潰**
  （例如 ACDC 從 33.5 掉到 6.0）——模型把所有像素都預測成 1~2 個類別，爛掉且卡死。
- 會「穩定」的方法（如 CoTTA）：不崩，但**永遠不進步**，跟不調適一樣。

**我們的目標：同時「高」（達到高 mIoU）又「穩」（撐到第 150 輪不崩）。**

### 0.3 為什麼會崩潰？（直覺）
模型微調時用的目標是「**讓自己更有把握**」（降低 entropy，見 §1.2）。但「有把握」不等於
「正確」。久了模型會偷懶——發現「全部猜 sky / road 最有把握」，於是越來越偏激，最後塌縮
成只猜 1~2 類。我們把這種失敗叫 **collapse（塌縮）**。

### 0.4 兩種退化模式（非常重要，後面所有設計都繞著它轉）
不同資料集「變爛」的方式不一樣：

- **塌縮型（ACDC、Cityscapes）**：類別分布塌到 1~2 類。徵兆是「類別多樣性」驟降——這個
  可以用 **H_margin**（§1.1）偵測到。
- **均勻退化型（VOC20）**：mIoU 只是「緩慢小幅下滑」（78.7→74.3），類別分布**仍然很多樣**，
  沒有塌縮。所以 H_margin **看不出來**（它一直很高 ≈3.0）。

> 一句話：**塌縮型有明顯警報訊號，均勻退化型沒有**。這是為什麼「一個 gate 通吃三個資料集」
> 很難——後面 §5 的 composite gate 就是為了解決這個。

## 1. 三個關鍵「訊號」（我們每處理一批影像能觀察到的量）

「訊號（signal）」= 我們在跑的過程中可以即時算出來、用來判斷「模型現在健康還是在變爛」的數字。
我們找了三個最有用的：

### 1.1 H_margin（類別分布的熵，class-marginal entropy）
- **怎麼算**：把一批影像所有像素的預測機率平均起來，得到「整體上每個類別被預測到的比例」
  （叫 class marginal，類別邊際分布）。再對這個分布算 **entropy（熵）**。
- **entropy（熵）是什麼**：衡量「分散 / 不確定」的程度。分布越平均（很多類別都有被預測到）
  → 熵越高；分布越集中（只猜少數類別）→ 熵越低。
- **直覺**：模型健康時會預測到很多類別 → H_margin 高；模型塌縮成猜 1~2 類 → H_margin 驟降。
- **用途**：塌縮的「警報器」。**但在 VOC20 上失靈**（VOC20 均勻退化、分布仍多樣，H 一直 ≈3.0）。

### 1.2 mean_conf（平均最大 softmax 機率，= 平均把握度）
- **softmax**：模型對每個像素會輸出「它屬於各類別的機率」，加起來=1。其中**最大的那個機率**
  就是「模型對這個像素最有把握的程度」（例如 0.9 = 九成把握這像素是 road）。
- **mean_conf**：把一張（或一批）影像所有像素的「最大機率」平均起來 = **模型整體的平均把握度**，
  介於 0~1。
- **直覺**：模型一邊適應、一邊變得越來越有把握 → mean_conf **隨時間單調上升**，在 mIoU 到達
  巔峰（peak）附近會跨過某個特定值。**重點：這個「單調上升」在三個資料集都成立，連 VOC20 也是**
  （不像 H_margin 在 VOC20 失靈）。
- **用途**：當作「**時機觸發器**」——「mean_conf 升過某個門檻 = 已經過了巔峰，該開始踩煞車了」。
  這就是你問的 mean_conf，它是 composite gate（§5）的核心。

### 1.3 grad_norm（梯度範數，gradient norm）
- **梯度（gradient）是什麼**：模型每處理一批影像，會算出「參數該往哪個方向、改多少」才能讓
  目標（降低 entropy）更好——這個「改動量」就是梯度。
- **grad_norm**：把這個改動量的大小用 L2 範數（各分量平方和開根號）量出來 = **「這一步模型想
  改動自己多劇烈」**。
- **學長的關鍵發現**（`docs/2026-06-18-contribution.md`）：grad_norm 跟 mIoU **高度負相關**，且呈
  **U 型**——剛開始（R1）高、隨著適應改善而**降到最低點（正好在 mIoU 巔峰）**、之後隨著 mIoU
  退化而**回升**。而且這個「退化時回升」在三個資料集都成立（連 VOC20 都抓得到）。
- **用途**：當「**退化的強度計**」——grad_norm 回升越多 = 退化越嚴重 = 該救得越用力。
- **重要陷阱**：grad_norm **就算健康時也很高且很吵**（單張影像之間在 2.7~88 跳動）。所以它只適合
  看「趨勢 / 強度」，**不能直接拿絕對值去設門檻、更不能直接塞進 loss 去壓**（見 §7 的失敗案例）。

### 1.4 一個訊號有兩種「用法」（學長提出的重要區分）
- **趨勢（trend）**：訊號跟 mIoU 的「漲跌幅度」對得上嗎？→ 適合當「連續煞車力道」。**grad_norm 勝**
  （在 VOC20 也有效）。
- **門檻（threshold）**：訊號隨時間「單調」嗎？單調的話「跨過一次門檻」就是乾淨的一次性觸發。
  → 適合當「何時開始動作」。**H_margin / mean_conf 勝**。

## 2. 共用底座：DeYO + MLMP（被微調的模型本體）

所有 gate 機制都是加在同一個「底座」上。底座本身會進步但會崩潰；gate 是用來「防崩」的外掛。

- **只微調 LayerNorm**：模型有上億參數，我們**只動其中的 LayerNorm（γ、β 兩組縮放/平移參數）**，
  其他全部凍結（包含文字編碼器）。LayerNorm 是每層用來「正規化」特徵的小參數，調它就能適應新環境，
  又不會大改模型。學習率很小（LR=5e-6）。
- **MLMP（Multi-Level Multi-Prompt）**：
  - **Multi-Prompt（多提示）**：用 7 句不同的文字描述（如 "a photo of a {}"）當類別錨點，取平均，較穩。
  - **Multi-Level / UAML（18 層特徵融合）**：不只用最後一層，而是融合 ViT 的 18 層特徵（淺層細節+深層語意）。
- **DeYO 的調適 loss（目標函數）**：
  - 目標是 **entropy minimization（最小化熵）**= 讓預測更有把握。
  - 但 DeYO 多了一道 **dual filter（雙重可靠度過濾）**：只用「夠可靠」的像素來學，條件是
    (a) entropy 夠低（已經有點把握）**且** (b) **PLPD** 夠高。
  - **PLPD 是什麼**：把影像的小區塊打亂（patch shuffle）後再預測，看預測變化多大。若打亂後預測
    崩掉 = 這個像素的判斷是「靠真正的物體形狀」而非背景猜的 → 可靠，採用。
- **協定**：持續、不重置、150 輪、固定亂數種子；每張影像「先評估（記錄 mIoU）再用它微調」。

**沒有任何 gate 時，這個底座會崩**（ACDC 33.5→6.0、Cityscapes 24.1→2.8）。下面每個機制都是一種防崩策略。

## 3. 機制一：divgate（H_margin gate → 拉回 source）★目前最強的基準
- **看什麼**：H_margin（§1.1），用一個 window（每 50 批）的平均值。
- **何時動作（三段式）**：
  - H_margin 高（≥ 門檻 h_threshold）→「aggressive」，**不救**（健康，放手讓它學）。
  - H_margin 中等 → 「cautious」，**輕度救**（restore 機率 = cautious_rst，約 0.5%）。
  - H_margin 低（< h_warning）→「brake」，**重度救**（restore 機率 = brake_rst，約 2%）。
- **怎麼救（restore 到哪）**：**拉回 source（原始未調適的模型）**。具體是「stochastic restore（隨機回復）」：
  每一步隨機挑一小比例（如 1%）的 LayerNorm 參數，把它們重設回最初的 source 值。等於「悄悄把模型
  往出廠狀態拉一點點」，抵銷它累積的偏差。
- **每個資料集的門檻**（H_margin 數值尺度因資料集而異）：ACDC h2.0/1.7、Cityscapes h2.1/1.8、VOC20 h3.0/2.7。
- **結果（學長，150 輪平均 mIoU）**：ACDC **31.8**、Cityscapes **23.6**、VOC20 **77.4**。在 ACDC/Cityscapes
  贏過 episodic 上界。**這是目前要打敗的標竿。**
- **弱點**：在 VOC20 上 H_margin 一直高於門檻 → gate 從不啟動 → 等於沒裝 gate（§0.4 的均勻退化盲區）。

## 4. 機制二：gradslope（grad_norm 斜率 → 拉回「過去的快照」）★你最想懂的這個
這是學長做的，我把它拆開講清楚它「到底在幹嘛」：

- **核心想法**：grad_norm 回升 = 模型在退化（§1.3 的 U 型右半邊）。所以**盯著 grad_norm 的「斜率」
  （slope，即它隨時間上升的速度）**，一旦它在「往上爬」就出手救。
- **看什麼**：把最近幾個 window 的 grad_norm 連起來，用最小平方法算一條直線的**斜率**。
  - 斜率 ≤ deadzone（死區，一個小門檻）→ grad_norm 平/降 → 模型健康 →**不救**。
  - 斜率 > deadzone → grad_norm 在升 → 退化中 → **救**。
- **怎麼救（關鍵差異！restore 到哪）**：不是拉回 source，而是拉回**「過去某個時間點的模型快照」
  （lagged snapshot）**。它每一步都把當下的 LayerNorm 存進一個佇列（deque），需要救時就從佇列裡
  挑「lag 步之前」的版本拉回去。**回拉多遠 = lag = lag_gain × 斜率**——斜率越陡（退化越急），就回拉
  到「越久以前的健康版本」。救的機率 = base_rst。
- **白話比喻**：divgate 是「出問題就回出廠設定」；gradslope 是「偵測到退化速度，退化越快就把模型
  時光倒流回越早之前的存檔點」。
- **我們的結果（150 輪，2026-06-22）**：**穩定、三個資料集都贏過 episodic，但都沒贏過 divgate**——
  VOC20 73.6（< 77.4）、ACDC ~31.4（< 31.8）、Cityscapes ~23.2（< 23.6）。而且 **deadzone 怎麼調幾乎沒差**
  （0.001~0.008 結果一樣）、**base_rst 0.01 比 0.02 好**（救太用力反而差）。
- **為什麼在 VOC20 輸**：VOC20 根本沒有塌縮要防，grad_norm 的回升是「正常的小幅退化」，gradslope 卻
  照樣出手 restore，反而**把 peak 壓低了**（救過頭，把模型本來能維持的高分拉下來）。

## 5. 機制三：composite gate（mean_conf 觸發 + grad_norm 調強度 → 拉回 source）★目前正在跑的新賭注
這是針對「gradslope 在 VOC20 輸」與「divgate 在 VOC20 盲」這兩個問題設計的：

- **拆成兩件事分別用不同訊號**（這是「composite=複合」的意思）：
  - **何時動（timing）→ 用 mean_conf**：mean_conf 在三個資料集都單調上升（§1.2），**連 VOC20 都會在
    peak 附近跨過某個值**。所以「mean_conf 升過 conf_ceil（門檻）」= 「已過巔峰、開始該防守了」→ 觸發救援。
    這正好補上 divgate 在 VOC20 的盲區（H_margin 在那不動，但 mean_conf 會動）。
  - **救多用力（depth）→ 用 grad_norm**：救援機率從 base_rst 起跳，隨著 grad_norm 升高最多放大到
    base_rst × grad_mult_max（退化越嚴重、救越用力）。
- **怎麼救**：拉回 **source**（跟 divgate 同款的隨機回復）。
- **假設**：用「通用觸發器（mean_conf）」+「強度計（grad_norm）」→ 應該能守住 VOC20 那個 divgate 守不住
  的 peak，同時在 ACDC/Cityscapes 一樣能擋塌縮。
- **正在跑的 sweep（2026-06-22）**：conf_ceil 取各資料集的「巔峰把握度」附近（ACDC {0.78,0.83,0.86}、
  VOC20 {0.68,0.71,0.74}、Cityscapes {0.66,0.69,0.72}）× base_rst {0.005, 0.01}。**結果：待出爐。**

## 6. 機制四：smooth_anchor（連續版的「拉回多久以前」）★現成、暫列後備
- divgate/gradslope 是「要嘛拉回 source、要嘛拉回固定 lag」；smooth_anchor 把「回拉多遠」做成**連續函數**：
  `lag(H) = lag_scale / (H − h_floor)`。H_margin 很高（≥ h_ceil）→ 完全不救；H 很低（≤ h_floor）→ 一路拉回
  source；中間 → 拉回一個「最近的快照」。
- **學長/先前 Phase M 的發現**：「把 h_floor 調高 → 更早退回乾淨的 source」會有幫助，但跟「調好的
  divgate」比其實是打平、沒有明顯勝出。所以這次先列後備，沒放進這批實驗。

## 7. 機制五：gradpen（把 grad_norm 塞進 loss 直接壓）❌ 失敗（但是有價值的負結果）
這是你最初的點子，我完整測過了，結論是**此路不通**，而且失敗的原因本身很有說服力：

- **想法**：既然 grad_norm 跟 mIoU 高度負相關，那就在 loss 加一項 `λ × ‖梯度‖²` 直接把它壓下去。
- **實測結果**：**找不到能用的 λ**——λ 太小 = 完全沒作用（跟沒加一樣）；λ 大一點 = **一步就崩潰**。
  改成「只罰超過健康基線的部分（excess / ema）」也崩；加 gradient clipping（限制步幅）也救不了。
- **為什麼失敗**（兩個致命原因）：
  1. grad_norm **健康時也很高很吵**（§1.3，尖峰到 88），所以「壓 grad_norm」會連「健康的學習」一起壓掉。
  2. 這一項的梯度方向（數學上是 entropy loss 的 Hessian 乘上梯度）**本身就是破壞性的**——所以限制「大小」
     沒用，問題出在「方向」。
- **結論（重要）**：**grad_norm 是好的「退化偵測器」，但是壞的「優化目標」。** 正確用法是拿它去「觸發
  /調控 restore」（→ §4、§5），而不是塞進 loss 去壓。這個負結果就是我們從「loss 路線」轉向「restore 路線」
  的依據——報告裡是個乾淨的轉折故事。
- 程式碼保留（λ=0 時與 divgate 逐位元相同），設計細節在 `docs/superpowers/specs/2026-06-21-gradnorm-penalty-design.md` §8。

## 8. 參考數字（150 輪平均 mIoU，越高越好）
| 資料集 | 不調適 | MLMP-episodic（上界，但要每張重置不實用） | DeYO+MLMP 無 gate | **divgate（要打敗的標竿）** |
|---|---|---|---|---|
| ACDC（4 種天氣） | 23.34 | 29.84 | 33.5→6.0 崩 | **31.8** |
| Cityscapes（5 腐蝕 sub100） | 20.6 | 20.0 | 24.1→2.8 崩 | **23.6** |
| VOC20（5 腐蝕 sub100） | 68.6 | 76.21 | 巔峰78.7→末74.3，平均77.4 | **77.4**（=無 gate，因 H_margin 在此不啟動） |

- **episodic（情節式）**：每張影像都「重置→調適→預測」，是品質上界，但要逐張重置、部署不現實，
  所以我們要在「不重置」的持續設定下逼近甚至超過它。

**一句話總結整個故事**：底座（DeYO+MLMP）會進步但會崩；我們試了「把 grad_norm 塞進 loss」失敗（證明它
是偵測器不是優化目標），轉而用三個訊號（H_margin 抓塓縮、mean_conf 抓過峰時機、grad_norm 抓退化強度）
去**觸發「把模型拉回乾淨狀態」的救援**。divgate（H_margin→source）目前最強；composite（mean_conf+grad_norm）
是衝著「在 VOC20 也能守住 peak」設計的最新嘗試，正在驗證。
